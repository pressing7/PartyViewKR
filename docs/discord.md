# 개인 디스코드 봇으로 PVKR 조작하기 (0.3.51)

각 사용자가 **자신의 봇을 만들고 자신의 PC의 PVKR에 토큰을 등록**합니다. 게임 PC가 Discord Gateway에 직접 연결하므로 별도의 Cloudflare Worker, 공용 중계 서버, 포트 개방이 필요하지 않습니다. 게임과 PVKR은 켜져 있어야 합니다.

## 1. 개인 봇 만들기

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 **New Application**을 누릅니다. 이름은 원하는 대로 정하고, 팀이 아닌 본인 계정 소유로 만듭니다.
2. **Installation**에서 **Guild Install**을 켭니다. **Install Link**는 **None**으로 두어도 됩니다. 초대 링크는 PVKR에서 제공합니다.
3. **Bot**에서 **Public Bot**을 끕니다. **Requires OAuth2 Code Grant**도 끈 상태로 둡니다. **Privileged Gateway Intents**는 모두 꺼도 됩니다.
4. **Bot → Token → Reset Token**으로 토큰을 발급하고 복사합니다. Application ID, Public Key, Client Secret과는 다른 값입니다. 토큰은 채팅·GitHub에 올리지 말고 PVKR 입력란에만 넣습니다.
5. **General Information → Interactions Endpoint URL**은 비워 둡니다. PVKR은 HTTP 수신 주소 대신 Gateway로 명령을 받습니다.

이미 다른 프로그램에서 쓰는 봇 대신 PVKR 전용 봇 하나를 만드세요. 같은 봇 토큰을 여러 게임 PC에 동시에 연결하지 않습니다.

## 2. 게임 PC 연결

1. 게임에서 `/pvkr`를 열고 **외부 접속 · 개인 디스코드 봇**을 펼칩니다.
2. **개인 봇 토큰**에 복사한 값을 붙여넣습니다.
3. **토큰 저장 및 시작 시 자동 연결**은 기본으로 체크되어 있습니다. 이 Windows 계정에서 암호화해 저장하고, 다음 플러그인 시작·업데이트 후 자동으로 연결합니다. 체크를 해제하면 이번 연결에서만 사용하고 다음 실행 때 다시 입력합니다.
4. **디스코드 연결 켜기**를 누릅니다.
5. **내 봇 초대 링크 복사**로 링크를 열고, 본인이 관리하는 Discord 서버에 봇을 초대합니다. 관리자 권한이나 메시지 내용 읽기 권한을 부여할 필요가 없습니다.
6. 연결 상태가 **연결됨**인지 확인합니다.

연결 후 포함된 **80개 직업·역할 이모지**를 개인 봇에 자동으로 준비합니다. 먼저 `기존 직업 이모지 확인 중`을 표시하고 등록된 목록을 조회합니다. 모두 있으면 `직업 이모지 준비 완료 · 80/80 · 기존 80개 재사용 · 새 업로드 0개`를 표시하며 이미지를 다시 올리지 않습니다. 없는 이미지에만 `새 직업 이모지 업로드 중`을 표시하고 업로드합니다. 파일 복사·서버 이모지 업로드·ID 입력은 필요하지 않습니다. 0.3.45의 `pvkr_` 이름은 같은 이모지 ID를 유지한 채 새 이름으로 변경하고, 추가된 역할 이미지 6개만 새로 등록합니다. 새 이름이 이미 있으면 그것을 우선 사용하며 다른 이모지는 삭제하지 않습니다. 준비 중에도 조회·수정·갱신을 사용할 수 있습니다. 일부 등록이나 이름 변경이 실패하면 기본 기호로 표시하며, 다음 연결에서 남은 것만 준비합니다. 기존 카드의 그림을 바꾸려면 다시 조회합니다.

기존에 토큰을 저장했다면 업데이트 후에도 그대로 자동 연결합니다. 저장하지 않았다면 한 번 입력하고 연결하세요. **디스코드 연결 끄기**를 직접 누르거나 브라우저 연결로 전환하면 다음 시작의 자동 연결도 끕니다. 토큰은 남아 있으므로 다시 사용할 때 입력란을 비우고 **디스코드 연결 켜기**를 누르면 됩니다. 플러그인만 종료·재시작하면 자동 연결 설정을 유지합니다.

다른 Windows 계정이나 PC에서는 저장한 토큰을 복호화할 수 없으므로 다시 입력합니다. **저장한 봇 토큰 삭제**는 저장본과 자동 연결 설정을 지우며, 현재 접속도 끊으려면 **디스코드 연결 끄기**를 누릅니다.

## 3. 휴대폰에서 사용

서버의 봇 프로필에서 DM을 열고 **`/pvkr`**를 입력합니다. 처음 명령이 목록에 나타날 때까지 잠시 걸릴 수 있습니다. 서버 채널에서 실행해도 응답은 본인에게만 표시됩니다. 실제 조작 권한은 봇 애플리케이션 소유자의 Discord 계정으로 제한합니다.

| 조작 | 동작 |
| --- | --- |
| `/pvkr`, 조회 | 게임에서 내 모집글을 새로 조회. 유효한 편집 내용이 있으면 `/pvkr`는 편집 카드 복원 |
| 갱신 | 현재 조건을 유지하고 갱신 |
| 수정 | **새 편집 카드**에 소개말·목적·모집 참가 조건·임무 찾기 설정·모집 범위·모집 역할 표시 |
| 직업 상세 | **별도 조회 카드**로 참가자의 등록 직업과 빈자리의 전체 허용 직업 표시 |
| 목적 구역 옆의 수정 | 목적·참가 조건·임무 찾기 설정·잡 중복 여부를 모두 하나의 입력창에서 수정 |
| 소개말 수정 / 비공개 설정 | 각각 별도의 입력창에서 수정 |
| 모집 역할 → 직업 수정 | 편집 카드에서 파티와 빈자리를 고른 뒤 허용 직업 선택 |
| 적용 및 갱신 | 모아 둔 변경을 한 번에 처리하고 갱신 |
| 최근 작업 결과 → 전체 결과 | 별도 카드에서 모든 결과 확인. 길면 이전·다음 페이지로 이동 |

조회 카드 맨 위에는 **조회·갱신·수정·수정창 닫기·알림 채널로 설정** 버튼을 표시합니다. 그 아래에는 요청 결과 안내, 던전 이름·인원·남은 시간, 활성 설정, 소개말, 파티별 자리표를 배치합니다. 별도의 `PVKR · 내 모집글` 제목은 표시하지 않습니다. 던전 이름 앞의 **🔒**는 비공개, **🌱**는 초행 및 초보자 환영을 뜻하며 해당 설정이 켜져 있을 때만 표시합니다.

활성 설정 구역은 소개말 위에 구분선으로 나눠 표시합니다. 첫 줄은 `[제한 해제] [최저 아이템 레벨로 참가] [초월하는 힘 무효화] [파티장 분배]`처럼 참가 규칙과 전리품 규칙을, 둘째 줄은 `[완료 목적] [미완료] [잡 중복 없음] [평균 아이템 레벨 555 이상]`처럼 모집 조건을 보여줍니다. 실제 선택한 값만 표시하며, 꺼짐·설정 안 함·일반 전리품·확인 불가 항목은 생략합니다. 모든 항목이 없으면 구역 전체를 생략합니다. 던전 이름은 설정하지 않았어도 표시합니다.

조회 카드에서는 파티 선택 메뉴 없이 **모든 파티의 자리 아이콘을 한 번에** 보여줍니다. 24인은 A~C, 48인은 A~F, 친선경기는 별빛팀·그림자팀·관전으로 나열하며, 각 파티의 이름·인원과 실제 등록된 자리만 표시합니다. 자리표 옆의 **직업 상세** 버튼을 누르면 참가자의 모집 등록 직업과 빈자리별 전체 허용 직업을 별도 텍스트 카드에서 파티별로 확인합니다. 마우스오버는 사용하지 않습니다.

아이콘 종류는 **조회한 모집글의 자리별 허용 직업**으로 정하고, 참가 여부로 체크 표시를 붙입니다. TH 모집 자리에 나이트가 들어와도 허용 조건이 TH로 남아 있으면 `join_tank_healer_role`입니다. 갱신 후 조회한 조건이 나이트로 바뀌면 `join_paladin_job`으로 바뀝니다. 참가자가 있는 자리도 모집 조건을 읽으며, 참가 직업으로 조건을 대체하거나 이전 카드의 조건을 추측해서 유지하지 않습니다.

허용 직업이 하나면 해당 잡·클래스 아이콘, 같은 역할의 여러 직업이면 방어·회복·공격 아이콘, 여러 역할에 걸치면 TH·TD·HD·THD 아이콘을 사용합니다. 각 역할에서 한 직업 이상만 허용해도 역할 조합에 포함하며 클래스도 해당 역할로 분류합니다. **모든 런타임 직업·클래스를 허용할 때만** `any_role`입니다. 정상적으로 등록된 지원 조합은 전부 이미지로 표시합니다. 이미지 미준비·알 수 없는 직업·정보 확인 불가 때만 **🟦 참가 · ⬜ 누구나 가능 · 🟨 직업 제한 · ⬛ 확인 불가**를 사용하며, 사용 중인 대체 기호의 범례만 한 번 표시합니다.

이름은 영문 전체 직업명과 종류를 사용합니다. 예: `paladin_job`, `gladiator_class`, `tank_role`, `healer_role`, `dealer_role`, `tank_healer_role`. 참가한 자리에는 `join_`을 붙입니다. 슬래시나 공백 대신 `_`를 쓰며 현재 80개 이름은 모두 2~32자 제한 안에 있습니다. 가장 긴 이름은 `join_tank_healer_dealer_role`(28자)입니다.

`내 모집글을 조회했습니다`는 고정 제목이 아닌 최근 조회 결과입니다. 갱신·수정 결과는 **최근 작업 결과** 구역에 표시합니다. **전체 결과**를 누르면 모든 항목의 적용·미적용·확인 필요 여부와 사유를 별도 카드로 확인합니다. 긴 결과는 **이전·다음** 페이지로 나누며, 항목 수와 글자 수 때문에 생략하지 않습니다. 모집글을 다시 조회한 뒤에도 직전 작업 결과를 열 수 있습니다. 요청 처리 중에는 진행 안내 카드로 바뀌었다가 결과와 최신 모집 정보로 돌아옵니다.

남은 시간은 조회 시각에 모집창의 남은 시간을 더한 **종료 예정 시각**을 Discord 상대 시간으로 표시합니다. 표기 문구와 갱신 간격은 Discord가 정합니다. 카드 이동으로 카운트다운을 다시 시작하지 않으며, 조회 뒤 게임에서 갱신한 내용은 **조회**를 눌러 새로 가져옵니다. 시간을 읽지 못한 경우 임의로 60분을 넣지 않습니다.

편집 카드는 별도 메시지이며 항목별 변경 전·후 값과 대기 개수를 보여줍니다. 직업 상세를 열거나 파티를 이동해도 변경사항은 유지합니다. 상세 카드의 파티 선택은 편집 카드와 별개입니다. **적용 및 갱신** 후에는 그 카드가 결과와 최신 모집 정보를 보여주는 조회 카드로 바뀝니다. 편집 내용이 남아 있을 때 이전 조회 카드에서 조회·갱신을 누르면 편집 카드에서 먼저 적용하도록 안내합니다.

| 편집 구역 | 항목 |
| --- | --- |
| 목적 | 목적, 초행 및 초보자 환영 |
| 모집 참가 조건 | 완료 조건 설정, 평균 아이템 레벨 |
| 임무 찾기 설정 | 제한 해제, 최저 아이템 레벨로 참가, 초월하는 힘 무효화, 전리품 규칙 |
| 모집 범위 | 비공개 설정 |
| 모집 역할 | 잡 중복 없음, 직업 수정 버튼 |

**목적 구역 옆의 수정**으로 일반 설정 전체를 한 입력창에서 변경합니다. 편집 목록의 켜짐·꺼짐은 **✅·❌**로 표시합니다. 입력창은 모집 목적 → 완료 조건 → 평균 아이템 레벨 → 전리품 규칙 순서이며, 구역명을 덧붙이지 않고 항목명만 표시합니다. 목적·완료 조건·전리품은 단일 선택, 아이템 레벨은 숫자 입력입니다. 나머지는 **사용할 옵션** 체크 목록에서 초보자 환영 → 제한 해제·최저 아이템 레벨·초월하는 힘 무효화 → 잡 중복 없음 순서로 표시합니다. Discord 입력창의 최상위 구성요소 제한이 5개이므로 체크 항목을 각 구역에 따로 배치하지 않습니다.

소개말과 비공개만 별도 입력창을 사용하며, 자리별 직업은 직업 수정 화면에서 선택합니다. 개별 켜기·끄기 버튼과 PVKR의 상시 안내 문구는 표시하지 않습니다. 입력창 아래의 양식 제출·민감한 정보 주의 문구는 Discord 자체 표시이며 공식 봇 API에 숨김 설정이 없어 유지됩니다. 전체 입력을 검사한 뒤 변경 대기 목록에 함께 담으므로 잘못된 입력이 있으면 일부 항목만 저장되지 않습니다.

24·48인 모집은 A~F 파티, 친선경기는 별빛팀·그림자팀·관전으로 나눕니다. 미등록 칸을 제외한 실제 자리 번호를 유지하며 참가자가 있는 자리는 편집할 수 없습니다. 직업 선택 메뉴는 아래 다섯 역할로 나눠 한 화면에 표시합니다. 각 목록에는 해당 역할의 잡과 클래스를 기존 PVKR 순서대로 배치합니다. 한 역할의 선택을 바꾸거나 비워도 다른 역할의 선택은 유지합니다.

| 직업 목록 | 함께 표시하는 클래스 |
| --- | --- |
| 방어 | 검술사, 도끼술사 |
| 회복 | 환술사 |
| 근거리 공격 | 격투사, 창술사, 쌍검사 |
| 원거리 물리 | 궁술사 |
| 원거리 마법 | 주술사, 비술사 |

**전체 선택·선택 비우기·방어·회복·공격** 버튼으로 빠르게 선택할 수 있습니다. 역할 버튼은 허용 직업을 해당 역할의 모든 잡·클래스로 바꿉니다. 공격 버튼에는 근거리 공격·원거리 물리·원거리 마법이 모두 포함됩니다. 허용 직업이 하나도 없는 변경은 적용할 수 없습니다.

소개말은 UTF-8 192바이트까지, 평균 아이템 레벨은 1~999입니다. 평균 아이템 레벨 입력에 **0**을 넣으면 제한을 끕니다. 비공개를 새로 켤 때는 **0000~9999의 숫자 네 자리**를 입력합니다. 이미 비공개이거나 이번 편집에서 비밀번호를 입력했다면, 입력창을 다시 열어 비밀번호를 비워 두어도 해당 값을 유지합니다. 다른 항목만 수정해도 기존 비밀번호는 유지합니다. 입력한 비밀번호를 카드·입력창에 다시 표시하거나 진단 로그에 남기지 않습니다.

콘텐츠에서 사용할 수 없는 조건은 기존 일괄 수정 동작대로 건너뛰고, 갱신 후 적용·미적용·확인 필요 개수와 사유를 안내합니다. 같은 참가자의 자리 mask가 등록 입장 직업 한 개로 좁아지는 게임 자동 변경은 허용합니다. 실제 참가자나 빈자리 모집 조건이 바뀌어 편집 기준이 달라지면 `/pvkr`로 다시 조회합니다. 편집 카드를 다시 열면 이전 편집 카드의 버튼은 만료됩니다. 직업 상세 카드도 다시 열면 이전 상세 카드의 선택 메뉴는 만료됩니다. 조회 카드는 별도로 유지되며, 적용을 마친 뒤에는 최신 결과 카드에서 조작합니다. 조작하지 않은 카드의 버튼·선택 메뉴는 15분 후 만료됩니다.

## 게임 채팅 수신

게임과 PVKR·디스코드 봇이 연결돼 있고 해당 종류의 수신을 켜면, **AFK 여부와 관계없이** 새 채팅을 Discord 서버 텍스트 채널로 전달합니다. 파티 채팅에는 일반 파티와 서버 초월 파티를 모두 포함하며, 귓속말은 받은 메시지만 전달합니다. 서버의 봇 소유자가 `/pvkr-chat`을 실행하고 옵션을 선택합니다. 모바일에서도 동일한 슬래시 명령을 사용합니다.

| 명령 예시 | 동작 |
| --- | --- |
| `/pvkr-chat 설정 종류:파티 채널:#파티채팅` | 파티 채팅의 수신 채널 지정 |
| `/pvkr-chat 설정 종류:귓속말 채널:#귓속말 멘션:everyone` | 귓속말 수신 채널과 everyone 멘션 지정 |
| `/pvkr-chat 설정 종류:연합파티 채널:#연합채팅` | 연합파티 채팅 수신 채널 지정 |
| `/pvkr-chat 멘션 종류:귓속말 설정:끄기` | 채널을 유지하고 해당 종류의 멘션만 끄기 |
| `/pvkr-chat 해제 종류:파티` | 해당 종류의 채팅 전달 해제 |
| `/pvkr-chat 상태` | 세 종류의 채널·멘션 설정과 전송·실패·제외·대기 건수 확인 |

`#파티채팅` 등은 예시이며 실제 서버의 텍스트 채널을 선택합니다. 같은 채널을 여러 종류에 지정할 수도 있습니다. 설정은 봇 애플리케이션 ID와 함께 저장하므로 같은 봇으로 재시작하면 복원하고, 다른 봇으로 연결했을 때 이전 채널에 보내지 않습니다. 수신/멘션 선택도 저장됩니다. 멘션은 새 설정에서 기본 꺼짐이며, 기존 설정의 채널을 바꿀 때 멘션 옵션을 생략하면 이전 값을 유지합니다. 설정 명령만 실행했을 때 테스트 메시지나 everyone 멘션을 보내지는 않습니다.

인게임 `/pvkr` → **외부 접속 · 개인 디스코드 봇** → **디스코드 채팅 전달**에서 각 종류의 **수신**과 **@everyone 멘션**을 따로 켜고 끕니다. 수신을 꺼도 채널/멘션 선택을 보존하므로 다시 켤 때 채널을 재등록하지 않습니다. 채널이 미설정이면 먼저 슬래시 명령으로 지정합니다. `/pvkr-chat 설정`은 해당 종류의 수신을 켜고, `멘션` 명령은 수신 상태를 바꾸지 않습니다. `해제` 명령은 채널 지정을 제거합니다. 인게임에서 꺼진 봇의 설정을 바꾸면 다음 연결에 반영합니다.

봇에 수신 채널의 **채널 보기·메시지 보내기·링크 임베드** 권한이 필요합니다. everyone을 켰다면 **@everyone, @here 및 모든 역할 멘션** 권한도 필요합니다. 이전 버전에서 초대한 봇은 채널 권한을 추가하거나 PVKR의 새 초대 링크를 사용할 수 있습니다. DM·스레드·포럼은 채팅 수신 채널로 지정하지 않습니다.

채팅은 **파티 파랑 / 귓속말 분홍 / 연합파티 주황**의 임베드로 전송합니다. 색은 왼쪽 표시줄에 적용되며 본문은 `닉네임@서버 : 채팅`입니다. 발신자 payload의 명시 서버 ID를 우선 사용합니다. 같은 서버 발신자에서 서버 정보가 생략되거나0인 경우 내 홈 서버로 보완합니다. 다른 서버 표시가 있는데 ID를 읽지 못한 경우에는 `서버 미상`으로 남깁니다. 홈 서버는 지역 이동의 일시적인 정보 공백 동안 보존하고 로그아웃/캐릭터 변경 시 초기화합니다. 긴 내용은 순서대로 여러 메시지에 나누어 보냅니다. everyone 설정이 켜진 종류는 첫 메시지에만 멘션을 붙이고, 이름이나 채팅 본문의 `@everyone`·사용자/역할 멘션은 실행하지 않습니다.

**채팅은 채널에 남는 일반 봇 메시지**이며 명령 응답의 만료 시간과 관계없습니다. 플러그인은 전송한 메시지를 자동 삭제하지 않습니다. 채팅 설정 명령의 답변은 본인에게만 표시하며, 기존 모집 조회·수정 카드의 표시/만료 동작은 바꾸지 않습니다. 채팅 전달은 모집글 조회 성공 여부에 의존하지 않습니다.

일시적인 연결 끊김 중에는 최대200건을 메모리에 보관하고 연결되면 순서대로 전송합니다. 한도를 넘으면 가장 오래된 대기 메시지를 제외하고 건수를 표시합니다. 로그아웃·캐릭터 변경·플러그인 종료는 대기 메시지를 버리고 진행 중 전송을 취소합니다. 채널/멘션 설정을 바꾸거나 수신을 해제하면 해당 종류의 대기 메시지만 버리며 이전 채팅을 새 채널로 보내지 않습니다. 전송 결과가 불확실한 네트워크 오류는 자동 재전송하지 않고 실패 건수로 남깁니다. `/pvkr-chat 상태`와 인게임 디스코드 설정에서 전송 상태를 확인할 수 있습니다. 과거 게임 채팅을 재조회하거나 로컬 채팅 기록 파일을 만들지는 않습니다.

## AFK 모집 완료 everyone 알림

알림을 받을 서버 텍스트 채널에서 `/pvkr` → **알림 채널로 설정**을 누릅니다. 봇에 그 채널의 **채널 보기**, **메시지 보내기**, **@everyone, @here 및 모든 역할 멘션** 권한이 필요합니다. 이전 초대 링크로 추가한 봇은 해당 채널의 권한을 추가하거나 새 초대 링크로 갱신할 수 있습니다. 일반 조회/수정 카드에는 멘션을 허용하지 않습니다. 완료 알림은 everyone을 사용하고, 게임 채팅 전달은 종류별 명령 설정을 따릅니다.

모집 중일 때 게임에서 AFK 모드를 켜고 첫 자동 조회로 정원을 확인합니다. 그 뒤 현재 파티 명단의 인원이 기억한 정원에 도달하면 **`@everyone 파티모집완료`**를 새 메시지로 전송합니다. 정원이 차서 모집글이 자동으로 종료돼도 재조회 성공을 기다리지 않습니다. 미등록 자리는 정원에 포함하지 않고, 친선경기 관전 자리는 포함합니다.

같은 완료 상태의 반복 관측은 한 번만 알립니다. 빈자리를 정상적으로 관측했다가 다시 차면 다시 알리며, 명단 읽기 실패만으로는 재알림하지 않습니다. 전송 실패 사유는 PVKR의 디스코드 설정과 새 조회 카드에 표시합니다. 전송 도중 결과가 불확실해지면 같은 완료 알림을 자동 재전송하지 않습니다. 채널 선택은 봇 애플리케이션 ID와 함께 저장하므로 다른 봇 토큰으로 연결해도 예전 채널에 알림을 보내지 않습니다.

## 연결이 안 될 때

- **0.3.35에서 첫 화면만 열리고 버튼은 응답 시간 초과**: 버튼 입력 처리 오류가 있으므로 0.3.36 이상으로 업데이트합니다. 다시 연결한 뒤 `/pvkr`로 새 화면을 엽니다. 기존 봇과 토큰을 그대로 사용합니다.
- **0.3.34 사용 중**: 명령어 등록 순서 오류가 있으므로 버튼 오류 수정도 포함된 0.3.36 이상으로 업데이트합니다. 기존 봇과 토큰을 그대로 사용할 수 있습니다.
- **연결 시작 실패**: PVKR에 표시된 `단계`와 오류 번호를 확인합니다. 봇 정보 확인과 명령어 등록 실패를 구분할 수 있으며, 문제를 제보할 때는 이 상태 문구만 보내고 토큰은 보내지 않습니다.
- **토큰 오류**: Developer Portal의 **Bot** 토큰인지 확인하고 다시 입력합니다. Reset Token을 다시 눌렀다면 이전 토큰은 사용할 수 없습니다.
- **팀 소유 앱 안내**: 본인 계정 소유의 별도 애플리케이션을 만듭니다.
- **봇은 연결됐지만 명령이 안 옴**: 봇을 서버에 초대했는지, `applications.commands` 권한이 포함됐는지, Interactions Endpoint URL이 비어 있는지 확인합니다. 명령 목록 반영 후 다시 입력합니다.
- **화면 만료 / 모집 정보 변경**: `/pvkr`로 다시 엽니다. 현재 기준이 유효하면 작성 중인 변경 목록을 유지합니다.
- **게임에서 처리 중**: 앞선 요청이 끝난 뒤 확인합니다. 연결 오류가 나도 이미 시작한 갱신을 자동으로 재실행하지 않습니다.
- **게임 수정창 / PVKR 편집 중**: 해당 작업을 먼저 끝낸 뒤 디스코드에서 다시 조회합니다.

같은 PC 브라우저, Cloudflare 외부 브라우저, Discord 연결은 한 번에 하나를 사용합니다. 기존 웹 기능은 유지합니다. AFK 모집 완료 알림과 게임 채팅 전달도 제공합니다. 알림/채팅 채널은 서버에서 명시적으로 지정하며 DM에서 하는 조회·수정·갱신과 별개입니다.

## 개발 검증

0.3.52는 관리형 테스트481개와 Python 배포 테스트12개 및 기존 DLL 참조의 오프라인 전체 소스 컴파일을 통과했습니다. 정식 Windows 패키지/Actions 빌드와 실제 게임·Discord 전송은 사용자 환경에서 확인합니다. 채팅 추가분은 legacy/현재 공개 채팅 이벤트의 읽기 전용 수신, 4개 채팅 코드의 3종 매핑, 발신자/서버/긴 Unicode 문장, 로그인·캐릭터·앱별 설정 분리, 인게임 종류별 수신/멘션 토글과 슬래시 명령의 직렬 저장, 홈 서버 생략 보완·명시 원격 서버 보존, 채널/멘션 변경과 해제, 전송 순서·권한·취소·대기 한도·불확실한 POST 비재시도를 검사합니다. 실제 SDK의 슬래시 명령 등록/파싱과 색상 임베드·allowed_mentions의 JSON 직렬화도 모의 REST/Gateway로 확인합니다. 소유자·앱 ID 확인, 중복 요청, 응답 접수 실패 시 실행 차단, 오래된 모집 정보, 친선경기·48인 자리, 다섯 직업 메뉴의 선택 보존, 역할별 클래스 포함, 비밀번호 0000, 일부 항목 실패 후 갱신을 검사합니다. 실제 Discord.Net 라이브러리에 모의 REST/Gateway 응답을 주어 연결 초기화, 새 편집·상세·전체 결과 메시지 생성, Components V2 응답과 제한, 버튼·선택 메뉴·통합 라디오·체크박스·소개말·비밀번호 입력 및 한 번의 일괄 갱신을 확인합니다. 59개 항목과 긴 문장·이모지의 결과 페이지 무손실 표시, 재조회 후 결과 유지, 읽기 전용 결과 카드, 직업 ID별 대체 표시, 전체 허용 직업 목록, 상세 조회 중 편집 유지, 상대 시간 기준 보존도 검사합니다. 80개 PNG 내장, 참가 직후 TH 조건 유지와 갱신 후 아이콘 변경, 클래스 포함 역할 조합, 이모지 재사용·부분 실패·취소, 봇별 ID 분리, 실제 SDK의 애플리케이션 이모지 목록·업로드·이름 변경 요청도 검사합니다. 이전 이름의 ID 보존, 부분 변경 실패 후 재개, 기존 새 이름 우선 사용, 48인 전체에서 가장 긴 이모지 이름의 메시지 제한도 확인합니다. 암호화한 설정 파일의 재로딩, 이전 버전 설정 복원, 저장 해제·삭제·직접 연결 끄기와 복호화 실패 시 설정 보존도 검사합니다. 완전히 종료한 뒤 새 클라이언트로 연결하여 기존 이모지의 ID 유지와 새 업로드 0건을 확인합니다. 실제 개인 봇 연결, Android Discord 화면, Windows 토큰 암호화 및 인게임 반영은 사용자의 환경에서 확인해야 합니다. Actions 빌드와 배포는 사용자가 실행합니다.

`ListingDiscordEmojiAssets`는 `src/DiscordIcons`의 80개 원본 PNG를 내장 리소스로 읽습니다. `ListingDiscordIcons`는 `job_{직업 ID}`·`anyone`·`role_t/h/d/th/td/hd/thd`와 각각의 `checked_` 키를 해당 봇의 이모지 ID에 연결합니다. 봇 연결마다 애플리케이션의 이모지 목록을 조회하고 현재 이름이 없으면 기존 `pvkr_` 이름을 ID를 유지한 채 변경하거나 새로 등록합니다. 관련 없는 이모지를 삭제하거나 바꾸지 않으며, 목록 조회에 실패하면 중복 업로드를 시도하지 않습니다. 등록은 Gateway 준비 후 비동기로 진행하고 Discord.Net의 속도 제한 재시도를 사용합니다. 연결 종료 시 취소하며, 이모지 준비 실패는 게임 조작 연결을 종료하지 않습니다. 비공개·초보자 환영은 기존 🔒·🌱 표시를 유지합니다.

구현은 [Discord Gateway](https://docs.discord.com/developers/events/gateway), [Interactions](https://docs.discord.com/developers/interactions/receiving-and-responding), [Components](https://docs.discord.com/developers/components/reference), [Discord.Net](https://docs.discordnet.dev/) API를 사용합니다. 봇 만들기 기본 절차는 [Discord 공식 시작 안내](https://docs.discord.com/developers/quick-start/getting-started)를 참고할 수 있습니다.
